KVM

edge-kvm becomes HyprKvm, the desktop half of HyprMobile. This study restyles the windows you already have in HyprMobile's look: black, white and one red, dot-matrix display type and monospace labels. It then mocks up the View screen on the desktop, so one computer can watch and drive another's focused window. Every mock is interactive. Nothing is sent anywhere.

01Same tokens as the phone.

The colours, radii and three faces come straight from HyprMobile's theme.css. A setting looks the same on both screens.

02Sized for a mouse.

Controls drop from 48 dp to 36 px and rows get denser. Cards, labels and the switch keep their shapes.

03Red means live.

Red marks something happening now: a stream, captured input or a destructive action. Everything else is white or grey.

04The phone's rules carry over to View.

Views open in Adjust, which sends nothing. Interact is a deliberate switch, and the frame takes all the space the header leaves.

Where it starts

The Settings window as it is today, redrawn from edge-ui. It's tidy, but it uses egui's stock dark theme with a blue accent and green status dots, and it shares nothing with HyprMobile.

Windows
Settings, Add a phone, Confirm pairing, and the tray menu. There's no main window: the tray is the app.
Palette
window, accent, ok, bad
Type
egui's default proportional face at 13.5 px, with no display or label face
  • The content and grouping are good, and they carry over unchanged
  • The plain-language copy already matches HyprMobile's voice
  • Only one long scroll, so status and actions share space with rarely used options
  • You can't see at a glance what's shared, what's live or who has control

The restyle keeps every row. It adds a Home screen for status and a View screen.

01

Home: a window that shows status

This is new. Today the status lives in the tray tooltip and at the top of Settings. Home is the window the tray's status row opens, laid out like HyprMobile's home: a hero card, then square tiles, one per thing being shared.

Hero
The peer's name, LINKED or WAITING, then address, round trip and uptime in labels
Arrangement
The "It sits to the" setting drawn as two screens. The red edge is the one you cross
Tiles
The big word is the current state. Clicking flips the common choice, and the footer says what will happen
Dots
Red means live now, white means on, grey means off
  • One glance answers what's shared and who has control
  • The tiles match the phone's, so Clipboard means the same on both
  • The View tile previews what you'll see, as the phone's Remote tile does
  • A new window adds a surface to keep in step with the tray
  • Should Home open on login, or only from the tray?

Click Control, Clipboard and Audio, or pick a side under Arrangement. The rail on the left jumps to the other sections.

Settings: the same rows on cards

Every row from today's window is still here, in the same order and with the same words. Each group is now a card with a monospace label, and an index on the left jumps between them. View is the one new group.

Rows
A grey label on the left, the control on the right, and a hairline between rows
Choices
Pill segments, selected in white, instead of blue tabs
Switches
The phone's switch: white when on
Save
A footer bar with the Save pill, and a note when saving restarts HyprKvm
Remove
A red ghost pill that asks again inline. There are no dialogs
  • The index stops the scroll from feeling endless
  • "Allowed" finally shows the per-device grants (remoteview, remoteinput, windowfocus) that are currently fixed at pairing
  • The grants table needs the receiver to accept changed grants, which it doesn't do yet
  • Should Start at login apply immediately, as it does today, while everything else waits for Save?

Pairing: the numbers are the hero

Both pairing windows already exist. The restyle makes the one thing you check the biggest thing on screen: the QR code on a white card, or the six-digit code in dot-matrix type, so you can compare it with the other screen from across the desk.

Phone
The QR code, a live countdown and a blinking dot while waiting. "Show link" replaces the collapsing header
Computer
"Pair with Tera?", the code, then the fingerprints in small monospace
Key changed
A red-outlined warning sits above the code, and Pair becomes "Pair anyway"
  • The wording on the phone and the desktop matches word for word: "Scan with HyprMobile"
  • A warning is the only red element, so it can't be missed
  • Doto digits need a size check below 48 px; 0 and 8 get close

05

View on the desktop

You see the other computer's focused window, streamed as HEVC by the receiver HyprMobile already uses. The phone's layout carries over: a header, then a full-bleed frame. The dock goes, because the desktop has a real mouse and keyboard. Only the Super arrows stay, as a small pad over the frame.

Header
Source and window title (a menu), Text/Media, Fit/Fill/1:1, sound, key capture, then the Adjust/Interact switch
Adjust
Drag pans, the wheel scrolls the picture, and double-click swaps Fill and Fit. Nothing reaches Tera
Interact
A red outline. Your pointer becomes Tera's pointer inside the frame. Click, right-click and the wheel go to Tera
Keys
Clicking the frame in Interact captures the keyboard, and the chip turns red. Ctrl + Alt gives the keys back
Super pad
Your own compositor takes Super, so the pad sends Super + arrow and the view follows the newly focused window
Source menu
Lists computers and Tera's windows. Follow focus is on by default. Pinning one window needs capture of windows that aren't focused, which comes later
Status
A readout shows codec, fps, bitrate and round trip, and clicking it hides it
States
Connecting, Locked, Tera in control and Not available all cover the frame and say what to do next
Pop out
Removes the rail, so View tiles as its own Hyprland window
  • The rules are the phone's, so moving between the two feels the same
  • Interact plus key capture works like a VM window, which most people already know
  • The receiver needs NVENC for HEVC today, so a desktop decoder is needed and the Windows host comes later
  • KVM edge crossing and View both drive Tera's input. Only one can hold the control lease
  • When you cross into Tera by the edge, should an open View step back to Adjust?

Switch on Interact, click the frame, then type. Press Ctrl + Alt to release. Try the Super pad, the source menu, and each state above.

To decide

Choices this study leaves open

egui or Tauri + Svelte

Everything here can be built in egui with custom widgets. Tauri would let Home, Settings and View share components and theme.css with HyprMobile directly.

Lean: Tauri on a migration branch, keeping edge-ui until it matches.

View as a page or its own window

A page in the rail keeps everything in one place. A separate window tiles better in Hyprland and allows two views at once.

Lean: a page that can pop out, as mocked.

The release chord

Ctrl + Alt is familiar from VMs but collides with some layouts. Alternatives are Right Ctrl, or Esc held for a second.

Lean: Ctrl + Alt, changeable under Settings → View.

Focused window, or more

Today the receiver captures the focused window's visible region. Whole monitors and pinned windows that aren't focused need new capture work.

Lean: ship follow-focus first; add Monitor as a source later.

View and edge crossing together

Moving into Tera by the screen edge while a View is in Interact gives two paths to the same input.

Lean: crossing the edge drops View to Adjust, with a toast.

Windows as a host

The Windows app only dials out and has no capture or encoder. Viewing a Windows PC needs Desktop Duplication and a hardware encoder.

Lean: list it in the source menu as "later" so the gap is visible.
